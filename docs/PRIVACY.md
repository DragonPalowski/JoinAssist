# Privacy and connections

JoinAssist runs in the SSMS process. It reads the current query text locally to identify sources, aliases, scopes and the completion position. It queries SQL Server catalog metadata for names, columns, definitions, dependencies and foreign keys. Metadata stays in the running extension's memory. From 0.7.0 it is cached for 2 minutes by default (configurable 1–15), isolated by native connection/session, server and database. **Aggiorna metadati** invalidates that scope. Bounded analysis caches also retain recent query text only in process memory.

It uses the active query tab's SSMS client connection information to open a metadata connection. With Microsoft Entra, compatible client tokens or token callbacks may be reused in memory. It does not save passwords or tokens, run a separate login service, or create credential files.

The extension does not execute the query text you are editing. It has no AI provider, analytics service, telemetry collection or external query transmission.

From 0.13.0, optional local choice memory (enabled by default) stores bounded SHA-256 identifiers derived from server/database, typed prefix and candidate identity, counts, UTC timestamps and a reset generation in `%LOCALAPPDATA%/JoinAssist/choices.json`. It contains no raw names, SQL, connection strings or credentials and is never sent to GitHub or another service. Hashes are local identifiers, not a promise of irreversible anonymization. **Impostazioni → Ricerca** disables ranking/recording or resets the stored choices. Writes happen in background, merge conservatively between processes and preserve reset generations. Another running instance can retain old in-memory hints until its next save/restart; choices immediately before exit may not persist. See [search behavior](SMART-COMPLETION.md).

From 0.12.0, the explicit DELETE dependency command reads fresh database-wide table/key/FK metadata and a VIEW DEFINITION permission check. The root filter and generated SQL stay in memory/the editor; no affected rows or row counts are queried. Confirming the preview only replaces editor text. The plugin never executes the generated transaction, changes SQL permissions or disables constraints. The script has a rollback default for manual review/execution; see [DELETE planning](DELETE-PLANNING.md).

From 0.5.0, opening **Aggiornamenti…** or clicking **Ricontrolla** sends an unauthenticated HTTPS request to the public GitHub Releases API for `DragonPalowski/JoinAssist`. Clicking **Scarica aggiornamento**, or **Installa alla prossima chiusura** from 0.10.0 when a download is needed, downloads the selected VSIX from that repository and GitHub's asset hosts. Requests include a JoinAssist user agent with the installed extension version; GitHub receives normal network information such as your IP address under its own policies. Query text, database/server names, account information, SQL credentials and Entra tokens are not sent. There is no background GitHub polling, GitHub login, stored GitHub token or telemetry.

Downloads are stored in `%LOCALAPPDATA%/JoinAssist/Updates`. Incomplete or invalid downloads are removed; verified VSIX files remain until you remove them. A plain download does not launch an installer. From 0.10.0 an explicit **Installa alla prossima chiusura** request authorizes launching Microsoft VSIX Installer after all SSMS processes close. Closing the update window cancels a network operation but does not cancel an already armed installation request; use its dedicated cancellation button. Version 0.4.1 has no update-check functionality.

Catalog visibility follows your SQL permissions. Local tooling, SSMS itself, database auditing and GitHub have their own behavior outside this extension's scope. If reporting a bug, share a synthetic schema and sanitized messages rather than real business queries, credentials or screenshots with connection details.

From 0.7.0, `%LOCALAPPDATA%/JoinAssist/preferences.json` contains user preferences only: automatic completion, timing, shortcut, acceptance keys, formatting and two-hop paths. It contains no query, connection, metadata or credential fields. **Copia diagnostica** puts extension/host versions and the diagnostic code on the clipboard; it does not send a report or include raw status messages, SQL, identifiers, account names or credentials.

From 0.9.0 the explicit star-expansion and object-information commands read the same catalog metadata; they do not execute the edited query or inspect its result rows. Incremental analysis retains only bounded, in-process text/token/AST caches. A first-run marker and JoinAssist's menu identity are saved in the active SSMS user's settings store to choose the main-menu default. Other menu entries are preserved and later user placement changes are not overridden. No connection/query information is stored in those settings.

From 0.10.0, an explicitly requested deferred update creates `%LOCALAPPDATA%/JoinAssist/Updates/Deferred/pending.json` and a versioned copy of the bundled helper in a unique subdirectory. The local record contains the target version, local package/SSMS/installer paths, size and SHA-256 values, request/expiry timestamps, worker PID/start time and a sanitized status code. It contains no SQL, database connection details or credentials and is not transmitted. The helper checks whether processes named SSMS are still running, waits up to 24 hours, and opens the normal host-adjacent Microsoft installer only after final integrity and process checks. It neither reads editor contents nor terminates processes. No service, scheduled task, Windows startup entry, network request or privilege elevation is created by the helper itself; Microsoft's installer can show its usual UI and permissions prompts. An interrupted request is not automatically resumed. Local helper/status files remain until you remove them after cancelling/completing the request.
