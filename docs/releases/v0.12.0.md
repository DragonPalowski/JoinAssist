JoinAssist 0.12.0 adds **Prepara DELETE con dipendenze…** for SSMS 22 x64.

### Use it

Write a complete single-table DELETE with a WHERE, place the cursor inside it and open **JoinAssist → Prepara DELETE con dipendenze…**. Inspect **Dipendenze e ordine** and **Script SQL**, then explicitly choose **Inserisci script di prova**. Only that DELETE is replaced; Ctrl+Z restores it. Cancelling changes nothing. The plugin reads catalog metadata only, never executes the DELETE or counts affected rows.

The draft captures all key scopes before deletion, keeps the root filter and composite FK pairs, unions multiple paths and orders children before parents. It distinguishes NO ACTION, CASCADE, SET NULL and SET DEFAULT. Cascade-only rows are left to SQL Server, with blocking descendants handled first.

### Review and boundaries

- The generated transaction **ends with ROLLBACK by default**. Manually change the marked final rollback to COMMIT only after reviewing/testing the full draft; keep error rollback intact. Variables in the original filter remain your responsibility.
- Require database VIEW DEFINITION and primary keys. Block cycles/self references, active DML triggers, enabled security policies, temporal/history/memory-optimized tables, unresolved metadata and oversized graphs. TOP/OUTPUT/OPTION/CTE/joined/cross-database or unfiltered root DELETEs are not supported in this first version.
- The draft guards against existing/implicit transactions, restores XACT_ABORT and uses locking hints/temporary key scopes. It sets ROWCOUNT 0, which remains a session setting. Testing a DELETE with rollback still uses locks and transaction-log resources.
- Foreign keys do not imply exclusive business ownership. Metadata visibility, concurrent/schema changes and application rules require your review. A blocked plan provides reasons and no insertable partial script.

Read [DELETE planning](https://github.com/DragonPalowski/JoinAssist/blob/v0.12.0/docs/DELETE-PLANNING.md) for supported syntax and limits.

### Update and validation

Use **JoinAssist → Aggiornamenti… → Installa alla prossima chiusura**, or download **JoinAssist-0.12.0.vsix**, verify **SHA256SUMS.txt**, save your queries, close SSMS and open the VSIX. Installation confirmations remain user actions.

Synthetic graph/parser/SQL-structure/metadata-reader/editor/UI tests and existing regression checks are run before publication; Microsoft's VSIX reader validates the package. No real DELETE, production database or installer is executed by tests. Live SQL Server DELETE, locking/concurrency and referential-action execution remains unverified by this automated suite: this is a draft-generation feature for controlled review/testing, not an execution engine.
