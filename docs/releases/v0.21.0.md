JoinAssist 0.21.0 adds configurable **EXEC / EXECUTE procedure and parameter completion** for SSMS 22 x64.

- Enable **Impostazioni → Completamento → Suggerisci procedure e parametri dopo EXEC / EXECUTE** (off by default). Type `EXEC GetOrd`, choose a procedure and accept it. The list shows schema-qualified names, parameter names, SQL types and OUTPUT/table-valued markers.
- Acceptance prepares a named-argument draft. Editable NULL fields use **Tab / Shift+Tab** to move between values; **Esc** ends field editing. OUTPUT and table-valued parameters receive collision-free declared variables. Populate generated table variables before calling the procedure; initialize OUTPUT variables yourself when the procedure also uses them as inputs.
- Existing arguments are preserved. After a comma, type `@` or a parameter prefix to complete remaining names; preceding positional arguments and existing `=`/values are respected. Use an explicit schema for ambiguous procedure names.
- Supports visible T-SQL and CLR procedures in the active database, including system procedures. Dynamic SQL, linked-server/cross-database calls, return assignments, temporary procedures and scalar-function EXEC forms are excluded. Conditional/procedural contexts and unsupported parameter types get name completion only. Metadata visibility depends on the connected account.
- Models list all visible parameters; NULL placeholders are not inferred default values. SQL Server does not expose T-SQL parameter defaults reliably through the parameter catalog: see [Microsoft's sys.all_parameters documentation](https://learn.microsoft.com/en-us/sql/relational-databases/system-catalog-views/sys-all-parameters-transact-sql). No procedure is executed or tested by JoinAssist.
- Procedure metadata uses the existing scoped cache. **Aggiorna metadati** also refreshes signatures. The built-in guide explains the workflow and limits.

### Update and validation

Use **JoinAssist → Aggiornamenti… → Installa alla prossima chiusura**, or download **JoinAssist-0.21.0.vsix**, verify **SHA256SUMS.txt**, save work and close SSMS before opening the VSIX.

Synthetic core/catalog/cache/model tests, editor insertion/connection-staleness cases and settings UI checks run alongside all existing suites. Microsoft's VSIX reader validates the package. No production SQL/procedure, user settings, installed plugin or installer is executed or modified by tests. Live SSMS completion and signatures under your account remain integration checks.
