JoinAssist 0.23.0 makes **DELETE dependency planning explain oversized or blocked graphs**, instead of leaving the dependency list empty.

- **Tabelle e percorsi** lists discovered tables even when the script is blocked. Search by table name or displayed-path FK, select a table and inspect a shortest route from the DELETE target, actual constraints/actions and all incoming explored FK column pairs. Cycles and alternate routes remain visible without claiming an executable deletion order.
- **Impostazioni → DELETE** configures generation limits: 1–512 tables and 1–4096 FK links. Defaults remain 64/256; old preference files inherit them. The preview includes an **Impostazioni DELETE…** button. Save and reopen the command to recompute.
- Counts describe schema relationships, not rows matching the WHERE. No data/count queries are added. Unsupported keys, cycles, triggers, security policies and table features still block generation. No dependencies are silently omitted and no partial script is insertable.
- Diagnostic exploration continues beyond generation limits, with independent technical caps of 2048 tables and 8192 FK links. A truncated or metadata-incomplete graph is clearly marked partial and cannot produce a script.

### Update and validation

Update through **JoinAssist → Aggiornamenti…**, or download **JoinAssist-0.23.0.vsix**, verify **SHA256SUMS.txt**, save work and close SSMS before installing.

Synthetic checks cover large graphs, raised/exact limits, shortest and alternate routes, cycles, partial diagnostics, cancellation, preference migration/persistence, read-only UI filtering/selection and dark/light themes. Existing completion, editor, execution-review and Microsoft VSIX package checks also run. No production SQL, real user preferences, installed extension or installer is modified by the tests. Live execution/concurrency of generated DELETE scripts and installed-SSMS UI remain integration checks.
