JoinAssist 0.10.1 fixes missing column proposals in **DELETE and UPDATE WHERE filters** for SSMS 22 x64.

For example, typing `DELETE FROM Orders WHERE Cu` now offers `CustomerId` when that column exists and is visible in the database metadata. Qualified names, aliases, FROM/JOIN sources, TOP, OUTPUT, hints, resolvable CTEs and local tables are handled. Filters include readable identity/computed columns, unlike INSERT/UPDATE assignment lists.

Only the name being completed is replaced. Existing predicates, suffixes and later statements remain intact. Sources from earlier statements are not inherited. The plugin analyzes an in-memory copy of the DML header and queries metadata only; it never executes the edited DELETE or UPDATE.

### Update

From 0.10.0, open **JoinAssist → Aggiornamenti… → Installa alla prossima chiusura** to download/verify this package and wait for all SSMS instances to close before opening Microsoft's installer. Complete its normal confirmations. You can cancel the pending request before launch. Manual download remains available.

From earlier versions, download **JoinAssist-0.10.1.vsix**, verify **SHA256SUMS.txt**, save your work, close all SSMS windows and open the VSIX.

### Validation

Synthetic regressions cover DELETE/UPDATE filters, schema/alias binding, joined and independent targets, CTEs, local tables, nested SELECTs, unfinished earlier statements, identity columns and exact replacement spans. The existing core/editor/menu/authentication/updater tests and Microsoft's package reader are checked before publication. No production database, edited DML or real installer is executed by these tests. Interactive validation in an installed SSMS query tab remains a live integration check.
