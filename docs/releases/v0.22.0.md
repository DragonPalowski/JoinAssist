JoinAssist 0.22.0 adds a configurable **warning before UPDATE / DELETE without WHERE** in SSMS 22 x64.

- Enabled initially under **Impostazioni → Completamento → Avvisa prima di eseguire UPDATE / DELETE senza WHERE**. It is independent of automatic suggestions. Old preferences receive the enabled default; an explicit opt-out is preserved.
- At SSMS **Query.Execute**, inspect the selected SQL, or the entire query tab when nothing is selected. Standard F5/Ctrl+E, menu and toolbar routes dispatching that command share the check. Custom commands, debugging and external applications are outside its scope. The integration uses [SSMS execution commands](https://learn.microsoft.com/en-us/ssms/quickstarts/work-with-query-results) and [the command BeforeExecute event](https://learn.microsoft.com/en-us/dotnet/api/envdte.events.commandevents?view=visualstudiosdk-2022).
- One dialog lists unfiltered UPDATE/DELETE targets and original line numbers. **Annulla** is the default for Enter/Escape and window close. **Vai all'istruzione e annulla** selects a reported statement. **Esegui comunque** allows only the pending original command, after rechecking text, selection, active editor and connection identity. No command is replayed by JoinAssist.
- Detect the outer statement's WHERE. A WHERE inside a subquery/CTE does not suppress a missing outer WHERE. TOP, joins, transactions and potentially unreachable control flow still warn. Comments, strings and procedure/function/trigger definitions are not immediately executed DML.
- Incomplete/unrecognized syntax, buffers over 500,000 characters, box selections and SQLCMD/multiserver show an incomplete-analysis notice requiring explicit review. Dynamic SQL, called procedure bodies and broad filters such as WHERE 1=1 are not assessed. A present WHERE is not proof that few rows will be modified.
- Everything is analyzed locally. No row-count/metadata query, credential cloning, SQL rewrite or automatic transaction is performed. The built-in guide documents behavior and limits.

### Update and validation

Use **JoinAssist → Aggiornamenti… → Installa alla prossima chiusura**, or download **JoinAssist-0.22.0.vsix**, verify **SHA256SUMS.txt**, save work and close SSMS before opening the VSIX.

Synthetic parser, settings, selection/snapshot/context, command-event and dark/light UI checks run with the existing suites. Microsoft's VSIX reader validates the package. No live SQL, user settings, installed extension or installer is changed by tests. Actual SSMS command routing and confirmation under your installed version remain manual integration checks.
