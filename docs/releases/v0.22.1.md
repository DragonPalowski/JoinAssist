JoinAssist 0.22.1 fixes **temporary-table suggestions in UPDATE / DELETE FROM joins** for SSMS 22 x64.

- Recognize FROM/JOIN/ON inside UPDATE and DELETE, including temporary tables populated by a prior `SELECT source.* INTO #temp`. Complete `JOIN #te` and qualified names such as `#temp.Col` in the same script.
- Keep local definitions while editing after completed `BEGIN TRAN`, IF/DROP guards or an earlier EXEC followed by a new declaration. Preserve conservative invalidation of local tables actually affected by uncertain DDL/procedure execution.
- Following COMMIT/ROLLBACK statements remain unchanged when inserting a JOIN name, predicate or column. Existing DML WHERE binding and SELECT-only alias rename behavior are preserved; CTE definitions do not see the DML FROM scope.
- SELECT INTO still does not copy foreign keys: a temporary JOIN name/column can be completed, but a matching column name alone does not produce an automatic ON relationship. Definitions must be earlier in the same script; another tab's session-local tables are not inspected.

### Update and validation

Use **JoinAssist → Aggiornamenti… → Installa alla prossima chiusura**, or download **JoinAssist-0.22.1.vsix**, verify **SHA256SUMS.txt**, save work and close SSMS before opening the VSIX.

Regression coverage reproduces the reported SELECT INTO / transaction / UPDATE JOIN structure with fictional names, verifies source-star columns through a synthetic metadata reader, and checks exact editor insertion before COMMIT. Existing parser, completion, alias-refactoring and execution-review suites run alongside Microsoft's VSIX package validation. No production SQL, transaction, user settings, installed extension or installer is executed or modified. Live completion in your SSMS/database remains an integration check.
