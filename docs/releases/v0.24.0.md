JoinAssist 0.24.0 adds **general JOIN/ON suggestions for temporary tables**, including arbitrary CREATE TABLE definitions rather than only snapshots of the same source.

- Works with resolvable local #temp and @table definitions earlier in the script: CREATE/DECLARE and SELECT INTO, normal-to-temp, temp-to-normal and temp-to-temp joins.
- Prefers complete keys/origin relationships where available, then offers lower-ranked equalities for same-name, compatible-type columns. Renamed direct projections and composite keys are supported when every required member is present. Unknown or ambiguous relationships are not invented.
- Every candidate is labelled **Temporanea · … · da verificare** and shows its ON. This is an inferred equality, not an inherited FK or a cardinality guarantee. The ordinary name-only alternative remains available; Tab inserts only the chosen proposal.
- Enabled initially through **Impostazioni → Completamento → Proponi ON per tabelle temporanee**. Declared local pairs can work offline; origin/base-table candidates need normal catalog metadata. Existing FK completion, DELETE planning and indentation behavior are preserved. See [temporary JOIN details](https://github.com/DragonPalowski/JoinAssist/blob/main/docs/TEMPORARY-JOINS.md) for scope and limits.

### Update and validation

Update through **JoinAssist → Aggiornamenti…**, or download **JoinAssist-0.24.0.vsix**, verify **SHA256SUMS.txt**, save work and close SSMS before installing.

Synthetic tests cover both directions, unrelated declared locals, snapshots/renames/composites, origin FK reads, type exclusions, ambiguity, offline names/columns, wide-table partial ON, settings and exact editor insertion. Existing suites and Microsoft VSIX validation run alongside them. No production SQL, temporary data, real user preferences, installed extension or installer is executed/modified by these tests. Installed-SSMS/database behavior remains an integration check.
