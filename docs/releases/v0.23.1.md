JoinAssist 0.23.1 fixes **missing FK JOIN proposals when another query follows the cursor**.

- A separate DELETE, SELECT, UPDATE or other recognized statement below the current JOIN no longer forces the popup into ordinary **Tabelle e viste** completion. The current JOIN and ON context remain available even if that following query is unfinished.
- Works with one-character, partial and full table names, simple partial ON expressions and resolvable CTE lineage. Earlier and later SQL, comments and whitespace remain untouched by insertion. Existing aliases and the prefix-only automatic/Tab indentation behavior are preserved.
- The fix still requires real visible FK metadata; it does not invent relationships, replace an existing ON clause or treat quoted names/literals as statement boundaries.

### Update and validation

Update through **JoinAssist → Aggiornamenti…**, or download **JoinAssist-0.23.1.vsix**, verify **SHA256SUMS.txt**, save work and close SSMS before installing.

Synthetic tests first reproduced the erroneous table-name fallback, then verify FK candidates, current-scope binding, suffix preservation, partial ON/CTE cases and exact Tab insertion through the editor controller. All existing regression suites and Microsoft's VSIX package validation also run. No live database/query, user preferences, installed extension or installer is modified by these tests; completion against your installed SSMS/database remains an integration check.
