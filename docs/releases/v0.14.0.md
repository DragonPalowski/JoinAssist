JoinAssist 0.14.0 fixes mouse selection and adds configurable SQL typing helpers for SSMS 22 x64.

- **Mouse fix:** single click selects the row under the pointer, Tab/Enter inserts it, and double click inserts that same row. The popup keeps typing focus in the editor and preserves the clicked choice across refreshes while it remains valid.
- **SQL keywords:** complete SELECT, FROM, WHERE, JOIN variants, GROUP BY, ORDER BY and common condition keywords with Tab. Context-specific, literal-prefix suggestions follow the existing casing preference. Standalone keywords need no database connection.
- **LIKE / NOT LIKE:** for a uniquely resolved text column, Tab prepares `'%%'` and places the caret between the percent signs. Nontext/unknown/ambiguous columns do not receive a LIKE template.
- **IN / NOT IN:** Tab prepares `('', '')` for comparable text, or `( ,)` for supported nontext scalar types, with the caret in the first value slot.

Use **JoinAssist → Impostazioni… → Completamento** to independently enable/disable **keyword completion** and **LIKE/IN templates**. Both are enabled by default. Existing RHS values/lists are preserved; generated placeholders are editable and no SQL is executed. Read [typing behavior and limits](https://github.com/DragonPalowski/JoinAssist/blob/v0.14.0/docs/TYPING-TEMPLATES.md).

### Update and validation

Use **JoinAssist → Aggiornamenti… → Installa alla prossima chiusura**, or download **JoinAssist-0.14.0.vsix**, verify **SHA256SUMS.txt**, save queries, close SSMS and open the VSIX.

Synthetic keyword/type/context/settings regressions and editor tests with generated WPF rows and routed mouse clicks check row identity, double-click/Tab insertion, stale query/connection refusal and cursor placement. Existing tests and GitHub core tests run before publication; Microsoft's VSIX reader validates the package. No edited SQL, production database or installer is executed by tests. The user's live SSMS session is not controlled by this automated suite.
