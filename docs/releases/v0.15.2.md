JoinAssist 0.15.2 improves **suffix-based name suggestions and one-step LIKE/IN completion** for SSMS 22 x64.

- **`pre_vw` → `prescriptions_vw`:** match the stem separately from a written terminal `_vw`/`_tb`. Prefer nearby literal stem prefixes over scattered-letter matches; preserve the actual inserted name, typo tolerance, literal schemas/local markers and accurate highlights. Full literal names/prefixes keep their priority.
- **One Tab for the complete filter:** after a known simple text column, `li`/`lik` directly offers `LIKE '%%'`; `not li` offers `NOT LIKE '%%'`. `no`/`not` can offer NOT LIKE and NOT IN. IN/NOT IN prepares quoted or unquoted slots according to the known type. Put the caret in the pattern/first value and preserve following statements.
- **Visible result:** filter rows show the whole pattern/list and a selected SQL preview, so a model can be distinguished from an ordinary keyword before accepting it.

The existing independent keyword/filter settings and keyword casing still apply. No type is guessed: ineligible/ambiguous/unknown types do not receive a typed model. Partial operators can retain ordinary keyword alternatives when enabled; those insert only the word/phrase and can work without a metadata connection. Typed models retain connection/query checks. Existing RHS patterns/lists/parameters and comments inside operators are not overwritten. No edited SQL is executed.

### Update and validation

Use **JoinAssist → Aggiornamenti… → Installa alla prossima chiusura**, or download **JoinAssist-0.15.2.vsix**, verify **SHA256SUMS.txt**, save queries, close SSMS and open the VSIX.

Synthetic tests cover the suffix-ordering regression, suffix highlights, tolerances, literal/local/schema boundaries, partial/full operators, type ambiguity, settings and ordinary keyword fallback. WPF/controller checks verify complete visible models, exact insertion/caret placement with later statements, and refusal of typed models without a current connection. Existing core/editor/theme/authentication suites run before publication; Microsoft's VSIX reader validates the package. No production database, edited SQL, user settings or real installer is executed by tests. Live SSMS behavior remains a manual integration check.
