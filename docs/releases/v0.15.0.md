JoinAssist 0.15.0 adds **single JOIN suggestions from shared foreign-key targets** for SSMS 22 x64.

- When two child tables reference the same complete parent key, **1 JOIN · FK comuni** proposes the equality between their actual child columns without inserting the parent table. Supports composite keys, renamed columns, existing aliases and directly mapped CTEs.
- The popup and manual JOIN picker distinguish this inferred relationship from a real direct FK and show the shared parent, predicate and any untrusted warning. Hover over a popup row for the full supporting FK names; the manual picker also includes them in its caption.
- Within each name-match band, actual direct FKs come first, then inferred single JOINs, then two-JOIN paths and ordinary table names. Parent-name affinity orders already-supported inferred alternatives. A duplicate inferred condition is omitted if an actual direct FK produces the same SQL.
- Existing paths remain available. **Impostazioni → Completamento → Proponi percorsi con 2 JOIN e collegamenti tramite FK comuni** controls both features. No new persistent setting or database change is required.

### Review the relationship

These are candidate equalities, **not direct foreign keys or guaranteed simplifications of a two-JOIN query**. Both child tables may have multiple matching rows. Skipping the parent can change results with orphan rows/untrusted constraints, parent filters or visibility restrictions, and the JOIN kind matters. Review the preview before accepting. No existing JOIN is removed automatically; ON/partial-ON completion remains based on direct FKs. Matching names alone never create a relationship.

### Update and validation

Use **JoinAssist → Aggiornamenti… → Installa alla prossima chiusura**, or download **JoinAssist-0.15.0.vsix**, verify **SHA256SUMS.txt**, save queries, close SSMS and open the VSIX.

Synthetic tests cover full composite-key matching with different ordinals/child names, disabled/untrusted constraints, different parents/keys, complete/incomplete CTE lineage, formatting, duplicate/history identity and ranking. Metadata-reader tests fetch the supporting constraint on the second hop; editor tests verify a single inserted JOIN, preserved following clauses and stale-connection refusal. Existing core/editor/theme/authentication suites run before publication, and Microsoft's VSIX reader validates the package. No production database, edited SQL, user settings or real installer is executed by tests. Live SSMS validation with a user's schema remains a manual integration check.
