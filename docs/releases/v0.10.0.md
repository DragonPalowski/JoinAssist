JoinAssist 0.10.0 adds **install at next close** for SSMS 22 x64.

### Use it

When a newer release is available, open **JoinAssist → Aggiornamenti… → Installa alla prossima chiusura**. JoinAssist downloads/verifies the package, then arms a small bundled waiting process. Close the Updates window and continue working. When all SSMS instances have closed and stay closed briefly, the helper rechecks the files and opens Microsoft's normal VSIX Installer. Complete its usual confirmations; JoinAssist does not close SSMS, confirm installation success or reopen it.

**Annulla installazione in attesa** cancels before installer launch. Status is shared across your SSMS instances. Requests expire after 24 hours. There is no service, scheduled task, Windows login autorun, background GitHub polling or automatic resume after logoff/reboot/worker failure.

### Integrity and behavior

- Verify SHA-256 and size on download and again immediately before launch; also verify the host installation's Microsoft installer has not changed.
- Bind the helper to the original request fingerprint and serialize cancellation/launch across processes. Do not launch a completed/cancelled/expired request twice.
- Keep manual download/install and folder access available. A plain download does not arm the worker.
- Retire waiting requests already covered by the loaded plugin version. No database, query or credentials are read by the helper.

### First upgrade

**From 0.9.0 or earlier, install 0.10.0 with the existing download → close SSMS → open VSIX procedure once.** The new button is delivered by this version and handles subsequent newer releases. It will stay disabled while 0.10.0 is the latest installed version.

Use **JoinAssist-0.10.0.vsix** and verify it against **SHA256SUMS.txt**. Save queries and close every SSMS window before the first installation.

### Validation

Shared state-machine/integrity tests, separate-process waiting/cancellation/quick-reopen tests with synthetic signals, WPF button/layout/resource checks, existing core/editor/authentication-contract/updater checks and Microsoft's package reader pass. The bundled worker is versioned with the plugin and has no SSMS assembly dependencies; the test-only worker is excluded from the package. No real installer or production SSMS session is launched/closed by tests. Actual VSIX Installer behavior on an installed SSMS configuration remains a live integration check.
