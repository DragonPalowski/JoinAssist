JoinAssist 0.15.1 fixes missing completion in queries that use **OPENJSON with CROSS APPLY / OUTER APPLY**, including long CTEs.

- An OPENJSON source no longer causes the whole FROM scope to be rejected. Table/column suggestions for ordinary aliases, and real FK JOIN proposals, remain available beside JSON sources.
- JSON aliases expose `key`, `value`, `type` with the default result schema, or exactly the names/types declared in `WITH`, including `AS JSON`. This is static SQL analysis: no JSON payload or business rows are read and no property names are guessed.
- Preserve ordinary base-column lineage through projected CTEs, while keeping JSON fields free of FK provenance. Retain existing alias/scope and cross-database restrictions. Completing a name replaces only that token and keeps the following SQL unchanged.

### Update and validation

Use **JoinAssist → Aggiornamenti… → Installa alla prossima chiusura**, or download **JoinAssist-0.15.1.vsix**, verify **SHA256SUMS.txt**, save queries, close SSMS and open the VSIX.

A synthetic CTE/OPENJSON regression reproduced the missing trigger before the fix. Tests now cover long CTEs with JSON_VALUE/conversions/CASE, chained APPLY, default/explicit schemas, partial and quoted tokens, correlation boundaries, catalog-name collisions, focused metadata loading, table/FK completion and exact editor insertion/stale-connection refusal. Existing core/editor/theme/authentication suites run before publication, and Microsoft's VSIX reader validates the package. No production database, edited SQL, user settings or real installer is executed by tests. Live SSMS validation remains a manual integration check.
